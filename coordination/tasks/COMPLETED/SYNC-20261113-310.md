- Aufgabenbeschreibung: Nach einem Nachhol-Lauf ('Catch up (minimum age)') erscheint im Verlauf ein zusaetzlicher leerer Eintrag 'Nothing to do'. Punkt 4 des Gerätetests (kein leerer Eintrag, wenn Foto-Ausloeser und Nachhol-Timer kurz nacheinander ablaufen) ist damit nicht erfuellt. Bitte klaeren, ob Soll-Verhalten, sonst beheben (z. B. Foto-Ausloeser/'Caught up'-Lauf ohne uebertragungsbereite Dateien nicht protokollieren).
- Technischer Kontext: Beobachtet (nicht Vermutung), API 29 (LeoSync_API29) und API 37, 0.17.0-debug, Mindestalter 1 min, Fotoprofil Photos: Fotos erzeugen (2-3 Stueck im Abstand ~10 s), sofort manuell 'Sync' -> sync-followup wird eingeplant (Frist = Reife des neusten Fotos). Reproduziert 3x: API 29 #13 'Catch up (minimum age)' 3 transferred gefolgt von #14 Photos 'Trigger: Caught up (start requested during a running sync)' 'Nothing to do'; API 29 #24 Catch up 2 transferred gefolgt von #25 Photos 'Trigger: New photos/videos' 'Nothing to do'; API 37 #122 Catch up gefolgt von #123-126 (je Profil 'New photos/videos', nothing to do, in der Liste zu '4x checked - nothing to do' gruppiert). Ursache unbekannt (Vermutung: Foto-Ausloeser trigger-content 90 s nach der letzten Aenderung bzw. 'Caught up' Lauf protokolliert auch ohne Arbeit). Ausserdem Info: Foto-Ausloeser laeuft fuer alle Profile inkl. Ordner-Profile (vorbestehend).
- Abhängigkeiten: SYNC-20261113-307
- Erwartetes Ergebnis: Entscheidung/Korrektur; kein Verlaufseintrag 'Nothing to do' direkt nach einem Nachhol-Lauf
- Durchgeführte Arbeiten: Keine Codeänderung. Benutzerentscheid 2026-11-13: Die «Nichts zu tun»-Einträge nach einem Nachhol-Lauf bleiben (Soll-Verhalten laut DECISIONS.md). Ursache: Foto-Auslöser trigger-content bzw. vorgemerkter Nachlauf («Caught up») starten einen vollen Lauf ohne Neues; der Nachhol-Auftrag selbst schreibt seit 0.17.0 keinen leeren Eintrag. Punkt 4 von SYNC-20261113-307 gilt damit nur für den Nachhol-Auftrag.
