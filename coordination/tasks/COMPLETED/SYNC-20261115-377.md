# SYNC-20261115-377 – Verbindungstest im Profileditor meldet bei unlesbarem Passwort einen Anmeldeversuch an den Server
- Erstellt am: 2026-11-15
- Absender: QA & Testing
- Empfänger: Development
- Priorität: MEDIUM
- Status: COMPLETED
- Übergabegrund: Begruendung MEDIUM: Sicherheitshaertung -334 (keine Anmeldung mit leerem Passwort) gilt im Lauf, aber nicht im Verbindungstest des Editors
- Aufgabenbeschreibung: QA-Prüfung 0.19.8 auf Emulator LeoSync_API29 (Android 10, root, Debug `ch.leo.sync.debug`): Ciphertext von `profiles.smbPasswordEnc` per sqlite3 verfälscht (erste vier Zeichen durch «AAAA» ersetzt, Länge unverändert). 1. LAUF (Sync): Der QA-Testserver (impacket, Log `.build\qa-smb-testshare.log.err`) sieht zwei Verbindungen («Incoming connection», «Closing down connection»), aber keine `AUTHENTICATE_MESSAGE`: BESTANDEN, keine Anmeldung. Die Meldung im Verlauf konnte nicht gezielt gelesen werden (ein anderes Profil scheiterte vorher am Ordnerzugriff). 2. VERBINDUNGSTEST im Profileditor («Test connection», Stufe «Wenn möglich», Passwortfeld unverändert): Der Server erhält `AUTHENTICATE_MESSAGE (\rbaldinger,)` gefolgt von «Could not authenticate user!»; die App zeigt «User name or password is wrong. Please check the profile». Das heisst: bei unlesbarem Ciphertext wird im Editor mit einem leeren oder falschen Passwort angemeldet. Erwartet: wie im Lauf eine verständliche Meldung «gespeichertes Passwort nicht lesbar, bitte neu eingeben» ohne Anmeldeversuch. Bitte `ui/ProfileScreen.kt` (Verbindungstest) und `CredentialCrypto.decryptResult` prüfen.
- Technischer Kontext: Stand 0.19.8. Aufbau: Profil «EncryptedSMB_2» importiert (Sicherung mit Export-Passwort), Pfad im Editor auf `\\127.0.0.1\QA` (Hostwechsel-Dialog bestätigt), Stufe von «Erforderlich» auf «Wenn möglich» (der Testserver bietet keine Verschlüsselung; bei «Erforderlich» bricht die App vorher korrekt ab). Zweiter Befund aus dem Test: Windows-Sicherheitsprotokoll des Servers zeichnet auf dem Test-PC keine Anmeldeereignisse auf (4624/4625/4776 leer, auch für erfolgreiche Anmeldungen), deshalb ist der Windows-Server für diese Prüfung nicht verwertbar.
- Betroffene Dateien: app/src/main/java/com/sync2pc/app/ui/ProfileScreen.kt, app/src/main/java/com/sync2pc/app/data/CredentialCrypto.kt
- Abhängigkeiten: SYNC-20261115-361
- Erwartetes Ergebnis: Ursache nachgewiesen, Korrektur mit Test; Rückmeldung an QA zur Prüfung am Emulator mit verfälschtem Ciphertext.
- Durchgeführte Arbeiten: ProfileScreen: unlesbares Passwort (decryptResult nicht Ok) wird beim Laden markiert; PasswordKeep.encFor behaelt den alten Chiffretext, solange kein neues Passwort eingegeben ist. Dadurch wirft der Verbindungstest (SmbSession.open) CredentialUnreadableException statt sich mit leerem Passwort anzumelden; Speichern loescht den Chiffretext nicht mehr. Version 0.19.9.
- Tests und Ergebnisse: EditorRulesTest (PasswordKeep, 3 Faelle); testDebugUnitTest gruen; Geraet nicht geprueft
- Folgeschritt: Pruefauftrag an QA (siehe Folge)
