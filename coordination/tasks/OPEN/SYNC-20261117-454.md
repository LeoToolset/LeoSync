- Aufgabenbeschreibung: 1. `FolderLayout` (Entities.kt) um fuenf Codes erweitern (Codes nie aendern, keine DB-Migration, Feld `profiles.folderLayout` bleibt): `MONTH_ONLY` (Jahr\MM), `YEAR_ONLY` (Jahr), `YEAR_COUNTRY_SUFFIX` (Jahr[ - Land]), `YEAR_COUNTRY_SUBFOLDER` (Jahr\[Land]), `FLAT` (Geraetestruktur). V1-V3 unveraendert. Eigenschaften je Code als reine Funktionen: mit Land ja/nein, Datumsanalyse ja/nein (FLAT nein), Rueckfrage-Ebene (Monat / Jahr / keine). Laender-Schalter = Zuordnung zwischen Codes (Konzept -450 Punkt 2), keine eigene Speicherung.
  2. Zielbestimmung (TargetResolver, `SyncEngine.targetPath`, `Job`): Pfade relativ zur **Basis** statt «unter dem Jahr», weil bei YEAR_COUNTRY_SUFFIX der oberste Ordner `2026 - Ägypten` ist. Semantik und Beispiele: Konzept -450 Punkt 3 (Heimatland/unbekannt = ohne Land; Landesname in App-Sprache, vorhandener Standardname anderer Sprache wiederverwenden). MONTH_ONLY verhaelt sich wie V1 ohne Land (Gruppen `JJJJ/MM/-`). Gespeicherte FolderMappings bestehender Profile (V1-V3, relativ zum Jahr) muessen unveraendert gelten: Umrechnung nur intern, keine Datenaenderung.
  3. Rueckfrage Jahres-Codes (Entscheid 4B): Abschnitt «Benutzerentscheide 2026-11-17» in -450 (Ausloeser, Gruppe mit Monat 0, Kandidaten je Code, fehlender Jahresordner bei YEAR_COUNTRY_SUBFOLDER). DecisionScreen und Benachrichtigung zeigen bei Monat 0 «ganzes Jahr» (Text DE/EN). `decisionSegments` je Code anpassen; Sanitisierung und Segmentgrenze (`mappingOf`) fuer Basis-relative Pfade pruefen.
  4. FLAT (Konzept -450 Punkt 4): Ziel `Basis\<RELATIVE_PATH-Segmente>\<Datei>`, jedes Segment `FolderNames.sanitize`; keine Datums-/Laenderanalyse (MediaAnalyzer nicht aufrufen), keine Rueckfrage, Duplikatsuche nur im Zielordner; Live-Foto-Video in seinem eigenen Ordner; Kollisionsregel unveraendert (gleicher Inhalt = vorhanden, sonst `_2`, nie ueberschreiben). Verschieben/Umbenennen auf dem Handy = erneutes Hochladen in den neuen Ordner, alte Kopie bleibt (Entscheid 5A).
  5. Standort: Codes ohne Land fragen nicht nach ACCESS_MEDIA_LOCATION (ProfileScreen Z. ~699/706 nur fuer Codes mit Land); Laenderabfrage nur fuer Codes mit Land.
  6. Nachbarordner-Duplikatsuche und SpaceFreer: Monats-Codes wie heute; Jahres-Codes Zielordner plus Jahresvarianten (`2026` ↔ `2026 - Land` bzw. `2026\Land`); FLAT nur Zielordner. `SpaceFreer.existsElsewhere` und `MonthFolderSearch` entsprechend (FLAT/Jahr ohne Monatshinweis).
  7. Unveraendert pruefen: FolderLayoutGuard (Sperre nach dem ersten Sync fuer alle Codes, Entscheid 3), ProfileOverlap (anderer Code = blockiert, auch MONTH_ONLY gegen V1), BackupCodec (neue Codes schreiben/lesen; alte App weist sie ab).
  8. Profil-Editor und Vorschau «Ordnerstruktur waehlen» nach UX-Entwurf -451 (Schalter, Familien Monat/Jahr/Flach, keine doppelten Eintraege; Beispiele aus Konzept Punkt 3/4). Texte nur in beiden Sprachdateien, `tools/make-translations.ps1`.
  9. Tests: TargetResolverTest je Code (mit/ohne Land, Heimat, andere Sprache, Rueckfrage Jahr inkl. Kandidaten und gespeicherter Entscheidung, bestehende V1-V3-Mappings unveraendert), FLAT-Pfade (Sanitisierung, Unterordner aus/an, gleicher Name in zwei Quellordnern getrennt, Kollision im selben Ordner `_2`), Zuordnung Schalter ↔ Code, BackupCodec, FolderLayoutGuard, ProfileOverlap.
  10. MINOR erhoehen (neue Funktion); Doku an Documentation (DECISIONS, DATA-MODEL Codes, SYNC-ENGINE Zielbestimmung, Hilfe); QA-Auftrag (alle acht Strukturen mit Beispielfotos inkl. Ausland/Heimat, Rueckfrage Jahr, FLAT mit WhatsApp-Pfad und gleichen Namen, Sperre, Sicherung alt/neu).
